## 控制器

控制器是 Netstamp 的中央服務，負責提供網頁應用程式與 API、驗證使用者和探測器、保存設定與量測資料、計算指派、評估警示規則、傳送通知，以及發布狀態頁面。

控制器本身不執行網路檢查；這項工作由探測器負責。

## 專案

專案是協作與授權的主要邊界，內含探測器、檢查、警示規則、通知目的地、事件與狀態頁面。

專案角色決定成員能在該專案中做什麼。系統管理是另一套權限：系統管理員不會自動成為每個專案的成員。

## 探測器

探測器是安裝在 Linux 主機上的輕量代理程式。每個探測器都會：

- 使用自己的探測器 ID 與 Secret 驗證身分。
- 向控制器回報心跳與中繼資料。
- 輪詢目前的檢查指派。
- 執行 Ping、TCP、HTTP 與 Traceroute 檢查。
- 暫存結果並提交給控制器。

請把探測器放在你想觀察目標的網路或區域。例如，你可以分別在資料中心、辦公室與雲端區域執行探測器。

## 檢查

檢查描述 Netstamp 應該量測什麼。

| 檢查類型   | 常見問題                   | 結果資料範例                              |
| ---------- | -------------------------- | ----------------------------------------- |
| Ping       | 探測器能否連到這台主機？   | 封包遺失與往返時間                        |
| TCP        | 探測器能否開啟這個連接埠？ | 連線成功與延遲                            |
| HTTP       | 這個網頁端點是否健康？     | 狀態、各階段耗時、內容比對與 TLS 憑證資料 |
| Traceroute | 經過哪條網路路徑抵達目標？ | 躍點、位址與每一躍延遲                    |

檢查也會定義執行間隔、逾時、啟用狀態與探測器選擇器。

## 標籤、選擇器與指派

標籤是附加在探測器上的鍵值中繼資料，例如 `region=tw`、`network=office` 或 `provider=aws`。檢查的選擇器會依據這些標籤挑選探測器。

Netstamp 會持續把檢查選擇器與已啟用探測器的標籤結合：

```text
check selector + enabled probe labels -> effective assignment -> probe execution -> result
```

空白選擇器會符合專案中所有已啟用的探測器。當探測器標籤、檢查選擇器或啟用狀態改變時，控制器會自動更新有效指派。

## 結果與分析

每個探測器都會獨立提交量測結果。Netstamp 保留原始結果，並建立時間序列檢視，讓你比較探測器、找出中斷、檢查 HTTP 耗時與憑證，以及分析 Traceroute 路徑。

使用專案總覽快速掌握健康狀態；需要深入調查時則使用 **分析**。

## 警示規則與事件

警示規則會在指定時間窗中評估某個檢查指標。若條件持續符合到達觸發時間，Netstamp 會開啟事件並傳送該規則的通知。

條件恢復後，事件會被解決；事件時間軸則會保留恢復後的操作紀錄。

## 狀態頁面

狀態頁面會在 `/status/<slug>` 公開專案中經過挑選的健康資料。它與需要登入的專案工作區刻意分離，只有明確加入狀態頁面的檢查才會公開。

## 各項資源如何串接

1. 成員建立專案並註冊探測器。
2. 探測器回報標籤與可用狀態。
3. 成員建立含有選擇器的檢查。
4. 控制器計算指派。
5. 探測器執行檢查並提交結果。
6. 警示規則評估結果並建立事件。
7. 通知目的地傳送事件更新。
8. 狀態頁面公開經過挑選的健康資料。

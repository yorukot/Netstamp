Netstamp 支援本機密碼、通用 OpenID Connect、Google OpenID Connect 與 GitHub OAuth。SMTP 則用於電子郵件驗證、密碼重設與電子郵件通知。

## 先設定公開來源

啟用身分供應商前，先在控制器環境設定有效的 HTTPS 來源：

```dotenv
PUBLIC_BASE_URL=https://netstamp.example.com
```

在各身分供應商註冊對應的 Callback URL：

| 供應商    | Callback URL                                                        |
| --------- | ------------------------------------------------------------------- |
| 通用 OIDC | `https://netstamp.example.com/api/v1/auth/external/oidc/callback`   |
| Google    | `https://netstamp.example.com/api/v1/auth/external/google/callback` |
| GitHub    | `https://netstamp.example.com/api/v1/auth/external/github/callback` |

公開來源屬於基礎設施設定，無法從管理介面修改。

## 通用 OIDC

開啟**系統管理 → 系統設定 → OIDC**，輸入 Issuer、Client 憑證、顯示名稱與即時帳號建立政策，並在啟用前驗證候選設定。

Issuer 必須提供有效的 OIDC Discovery Metadata，且與 Discovery 回傳的 Issuer 相同。驗證成功代表端點可用，但仍須測試完整的瀏覽器登入流程。

## Google

在**系統管理 → 系統設定 → Google**輸入 Google Client 憑證與選填的 Hosted Domain Allowlist。只有在 Google 應用程式接受的所有個人與 Workspace 帳號都能使用時，才將 Allowlist 留空。

## GitHub

在**系統管理 → 系統設定 → GitHub**輸入 GitHub Client 憑證、即時帳號建立政策與 Provider Signup Policy。

Provider Signup 只控制 GitHub 授權頁面的選項，不會覆寫 Netstamp 全站的帳號建立政策。

## 先連結既有管理員

初次設定時，先停用即時帳號建立：

1. 使用初始系統管理員登入。
2. 開啟**帳號設定 → 登入方式**。
3. 連結外部身分。
4. 登出後，在無痕視窗測試供應商登入。
5. 確認登入後開啟的是同一個 Netstamp 帳號。

確認成功後，再考慮變更本機密碼或帳號建立政策。

**系統管理 → 系統設定 → 存取**中的帳號建立選項，是本機註冊與供應商 JIT 的總開關。只有總開關與該供應商的 JIT 都啟用時，供應商才能建立新使用者。

## 設定 SMTP

開啟**系統管理 → 系統設定 → SMTP**，輸入郵件伺服器、寄件人、憑證、TLS 模式與逾時，儲存後傳送測試郵件。

支援的 TLS 模式為 `starttls`、`implicit` 與 `none`。只有連線位於可信任的私有網路，且已由其他傳輸層保護時，才使用 `none`。

密鑰會以 `SYSTEM_SETTINGS_ENCRYPTION_KEY` 加密後存入資料庫。請維持這個 Key，並在復原資料中保存加密副本。

## 測試完整流程

1. 從系統設定傳送 SMTP 測試郵件。
2. 在**警示 → 通知**建立電子郵件目的地並傳送測試。
3. 使用拋棄式帳號要求密碼重設郵件。
4. 若要求電子郵件驗證，註冊拋棄式帳號並開啟驗證連結。
5. 在已登出的無痕視窗測試每個已啟用的外部供應商。

:::warning在確認獨立復原路徑以前，不要停用管理員最後一個可用的身分驗證方式。:::

存取政策與使用者管理請參閱[系統管理](/zh-TW/docs/guides/system-administration/)。

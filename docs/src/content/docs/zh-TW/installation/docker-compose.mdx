Repository 提供的標準 Compose 部署是自架的建議起點，會執行三個服務：

| 服務       | 用途                                                   |
| ---------- | ------------------------------------------------------ |
| `postgres` | PostgreSQL 16、TimescaleDB 與持久化 Named Volume       |
| `migrate`  | 使用相同 Netstamp Image 版本執行一次性資料庫 Migration |
| `netstamp` | 控制器、內嵌 Web App、API 與 Linux 探測器安裝檔案      |

Stack 會發布單一控制器 Port，不包含 Reverse Proxy 或 TLS 自動化。

## 下載 Release 檔案

```bash
mkdir -p /opt/netstamp
cd /opt/netstamp
curl -fsSLO https://github.com/yorukot/netstamp/releases/latest/download/compose.yaml
curl -fsSLO https://github.com/yorukot/netstamp/releases/latest/download/.env.example
cp .env.example .env
chmod 600 .env
```

## 產生必要密鑰

產生五組獨立數值：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

把不同數值分別放入 `.env`：

```dotenv
DATABASE_PASSWORD=<random value>
LOG_PSEUDONYM_KEY=<random value>
SYSTEM_SETTINGS_ENCRYPTION_KEY=<random value>
AUTH_SESSION_HASH_KEY=<random value>
AUTH_API_TOKEN_HASH_KEY=<random value>
```

重新啟動與升級時必須維持這些數值。變更 Hash Key 會讓相關憑證失效；變更 Settings Encryption Key 可能使已保存的 SMTP 與外部供應商憑證無法讀取。

## 啟動 Stack

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs migrate
```

預期狀態如下：

- `postgres` 為 Healthy。
- `migrate` 以狀態 0 結束。
- `netstamp` 正在執行。
- 發布的 Port 可回應兩個 Health Endpoint。

```bash
curl --fail http://127.0.0.1:3000/healthz
curl --fail http://127.0.0.1:3000/api/v1/healthz
```

本機安裝可開啟 `http://127.0.0.1:3000`。第一個建立的帳號會成為系統管理員。

## 固定 Image 版本

可用的 Image 選項如下：

```dotenv
NETSTAMP_IMAGE=yorukot/netstamp
NETSTAMP_VERSION=latest
TIMESCALEDB_IMAGE=timescale/timescaledb:2.20.3-pg16
NETSTAMP_PORT=3000
```

GitHub Release 所附 Compose 檔案預設使用該 Release 的 Netstamp Tag；Repository 版本則使用 `latest` 方便評估。受控環境應將 `NETSTAMP_VERSION` 與 `TIMESCALEDB_IMAGE` 固定為測試過的 Release Tag 或 Digest。

Migration 與應用程式服務永遠使用相同 Netstamp Image 版本。

## 持久化資料

資料庫位於邏輯名稱為 `netstamp-postgres` 的 Compose Volume；Docker 通常會在實際名稱前加上 Compose Project Name。移除 Container 不會移除 Volume。

```bash
docker volume ls --filter name=netstamp-postgres
docker compose exec postgres psql -U netstamp -d netstamp -c 'select now();'
```

:::caution 除非確定要銷毀資料庫 Volume，以及所有使用者、專案、探測器、結果、事件與設定，否則不要執行 `docker compose down -v`。:::

## 建立本機 Image

若要從 Checkout 建立與 Release 相同的 Image Layout：

```bash
docker build -f deployments/Dockerfile -t netstamp:local .
NETSTAMP_IMAGE=netstamp NETSTAMP_VERSION=local docker compose up -d
```

Image 包含控制器、Migration、Web App，以及 `amd64` 和 `arm64` 探測器 Binary。

對外發布 Netstamp 前，請繼續檢查[設定](/zh-TW/docs/installation/configuration/)並完成 [Reverse Proxy 與 HTTPS](/zh-TW/docs/installation/reverse-proxy-and-https/)。

Netstamp 除了本機密碼，也支援通用 OpenID Connect、Google OpenID Connect 與 GitHub OAuth。外部身分提供者可用於登入、敏感操作前的近期身分確認，以及將外部身分連結到既有帳號。

## 先設定公開來源網址

公開來源網址屬於基礎設施設定，無法從系統管理介面變更。啟用身分提供者前，先在控制器環境中設定有效的 HTTPS 來源網址：

```dotenv
BACKEND_BASE_URL=https://netstamp.example.com
PUBLIC_WEB_BASE_URL=https://netstamp.example.com
```

再到身分提供者註冊相符的回呼網址：

| Provider     | Callback URL                                                        |
| ------------ | ------------------------------------------------------------------- |
| Generic OIDC | `https://netstamp.example.com/api/v1/auth/external/oidc/callback`   |
| Google       | `https://netstamp.example.com/api/v1/auth/external/google/callback` |
| GitHub       | `https://netstamp.example.com/api/v1/auth/external/github/callback` |

## Generic OIDC

到**系統管理 → 系統設定 → OIDC**輸入 issuer、用戶端憑證、顯示名稱與 JIT 政策，驗證候選設定後再啟用 OIDC。

Issuer 必須提供有效的 OIDC discovery metadata，且 discovery 回傳的 issuer 必須完全相符。驗證功能會檢查端點是否就緒，但仍須實際測試完整的瀏覽器登入流程。

## Google

在**系統管理 → 系統設定 → Google**輸入 Google 用戶端憑證與選用的 hosted-domain 允許清單。只有在 Google 應用程式接受一般個人帳號，而且所有 Workspace 帳號都符合政策時，才應將允許清單留空。

## GitHub

在**系統管理 → 系統設定 → GitHub**輸入 GitHub 用戶端憑證、JIT 政策與提供者註冊政策。提供者註冊只控制 GitHub 自己的授權頁面選項，不會覆寫 Netstamp 的帳號建立政策。

## 既有使用者與 JIT 帳號建立

初次設定時，先維持 JIT 帳號建立功能關閉。以第一位系統管理員登入，到**帳號設定 → 登入方式**連結外部身分；變更本機密碼或帳號建立政策前，先用無痕視窗實際測試外部登入。

「**系統管理 → 系統設定 → 存取**」中的帳號建立是本機註冊與提供者 JIT 的主開關。只有在這個開關與該提供者的 JIT 設定都啟用時，提供者才能建立使用者。任一開關關閉時，尚未出現過的外部身分都不能建立帳號；將該身分連結到既有使用者後，仍可正常登入。

## SMTP

電子郵件通知、密碼重設與電子郵件驗證都需要 SMTP。請從**系統管理 → 系統設定 → SMTP**輸入並儲存，再使用 SMTP 測試功能確認寄送正常。

支援的 TLS 模式為 `starttls`、`implicit` 與 `none`。只有連線位於可信任的私有網路，而且已有其他傳輸層保護時，才可使用 `none`。

系統管理介面會將設定存入資料庫，並使用 `SYSTEM_SETTINGS_ENCRYPTION_KEY` 加密機密值。請固定使用同一把加密金鑰，並妥善備份。

## 測試完整流程

1. 在**系統管理 → 系統設定 → SMTP**儲存並測試 SMTP 設定。
2. 到**警示 → 通知**建立 Email 通知並傳送測試訊息。
3. 使用可拋棄的帳號請求密碼重設信。
4. 若已要求驗證電子郵件，註冊一個可拋棄帳號並開啟驗證連結。
5. 驗證並儲存每個外部身分提供者，再於登出後的無痕視窗逐一測試實際登入流程。

在確認有另一條可用的復原途徑前，不要停用系統管理員最後一種仍可登入的驗證方式。

系統管理員負責整個站台的存取與服務設定。此角色與專案角色分開，不會自動取得所有專案的監控資料。

## 建立初始管理權限

新站台建立的第一個帳號會成為系統管理員。請有意識地建立此帳號、使用強健登入方式保護，並在站台正式運作前加入第二位受信任的管理員。

Netstamp 會阻止移除最後一位系統管理員。

## 存取政策

使用管理設定控制誰能建立帳號，以及如何從核准的身分供應商即時建立外部身分。依部署需求，註冊可以開放、限制或由 JIT Provisioning 控制。

正式環境應使用明確政策，並分別用核准與未核准的身分驗證。

## 驗證供應商

管理員可設定全站通用 OIDC、Google 與 GitHub 登入。Provider 憑證、Callback URL、Claim Mapping 與 Allowlist 會影響所有選擇該方式的使用者。

修改供應商設定時，至少保留一種測試過的復原登入方式。部署設定與 Callback URL 請參閱[驗證與電子郵件](/zh-TW/docs/installation/authentication-and-email/)。

## SMTP 與電子郵件

SMTP 設定支援電子郵件驗證、密碼復原與 Email 通知目的地。修改 Host、憑證、寄件人或 TLS 後都要傳送測試郵件。

若 SMTP 無法使用，請在強制套用依賴電子郵件的政策前，先確認哪些帳號復原與通知管道會一併失效。

## 管理使用者與管理員

具權限的管理員可在管理區檢視使用者、變更帳號狀態，以及授予或移除系統管理員權限。

停用帳號前：

- 檢查是否為任何專案的最後一位擁有者。
- 移交與帳號綁定的自動化或 API 權杖。
- 檢查是否為必要的系統管理員。
- 保留政策要求的稽核或事件脈絡。

專案成員資格必須在各專案中管理。

## 資料管理

管理員匯出與匯入工具可支援遷移或受控的資料維護。匯出檔可能包含站台設定與使用者相關資料，應視為敏感資料。

完整災難復原請使用資料庫與 Volume 備份，不要只依賴應用層匯出。請參閱[備份與還原](/zh-TW/docs/installation/backup-and-restore/)。

## 維運實務

定期檢查管理員、帳號建立政策、外部供應商、SMTP 傳送與閒置帳號。記錄全站安全設定變更，並在真正需要以前先測試復原路徑。

**分析**會把探測器回傳的量測資料整理成摘要、時間序列、憑證證據與路徑診斷。快速查看健康狀態時使用專案總覽；需要回答特定問題並保存調查範圍時，則使用分析。

本指南說明所有分析檢視共用的控制項。準備開始判讀結果時，請繼續閱讀[分析 Ping、TCP 與 HTTP](./analyze-measurements/)或[調查 Traceroute](./investigate-traceroute/)。

## 建立分析範圍

分析範圍是符合目前選取條件的有效探測器與檢查指派：

**所選探測器 × 所選檢查 × 有效指派 = 顯示的結果**

這兩個選擇器是篩選條件，不是彼此獨立的查詢。Netstamp 只會顯示具有有效指派的配對。

### 1. 選取探測器

開啟**選取探測器**，選擇一或多個探測器。你可以逐一瀏覽探測器，也可以選取帶有 `region:tw` 或 `provider:cloud` 等標籤的所有探測器。

<ProductScreenshot src={probePickerScreenshot} alt="依個別探測器與探測器標籤分組的分析探測器選擇器" caption="先決定要從哪些網路位置觀察；選取標籤時，會展開為目前帶有該標籤的探測器。" />

所選探測器範圍會決定下一步有哪些檢查可用。若替換探測器選取項目，Netstamp 會移除在新範圍內已無有效指派的檢查。

### 2. 選取檢查

選取探測器後，開啟**選取檢查**。你可以瀏覽所有符合的檢查，或依 Ping、TCP、Traceroute、HTTP/HTTPS 縮小清單。

<ProductScreenshot src={checkPickerScreenshot} alt="選取探測器後依檢查類型分組的分析檢查選擇器" caption="檢查清單只包含已指派給所選探測器的檢查，因此無法選取不存在的探測器與檢查配對。" />

不一定要同時限制範圍兩側：

| 選取方式             | 顯示結果                                       |
| -------------------- | ---------------------------------------------- |
| 一個探測器與一個檢查 | 一筆精確指派的詳細檢視                         |
| 多個探測器與一個檢查 | 比較同一個檢查在不同網路的結果                 |
| 一個探測器與多個檢查 | 比較同一個網路上的不同檢查                     |
| 多個探測器與檢查     | 依檢查類型分開，每個符合的有效指派各有一條序列 |

若要比較某個檢查的所有已指派探測器，先選取該檢查，再清除探測器選取項目，但不要使用**重設範圍**。保留下來的檢查會成為唯一篩選條件。

### 3. 確認解析後的範圍

面板標題會顯示精確的探測器到目標路徑，或目前選取的指派數量。判讀或分享圖表以前，先確認這個標題。

<ProductScreenshot src={scopeControlsScreenshot} alt="選取一個探測器、一個檢查、相對時間範圍與更新控制項的分析頁" caption="範圍只解析成一筆指派時，分析會開啟完整指標與結果面板。" />

<ProductScreenshot src={multiSeriesScreenshot} alt="三個探測器與一個 Ping 檢查解析為三筆指派的分析頁" caption="多筆指派會切換成比較模式，為每個符合的探測器與檢查配對顯示一條序列。" />

使用**重設範圍**會移除所有探測器、檢查、舊版指派參數與目前選取的 Traceroute 執行。時間範圍與更新偏好則會保留給下一次調查使用。

## 控制時間區間

開啟**時間**，選擇相對預設範圍或精確的絕對區間。

<ProductScreenshot src={timePopoverScreenshot} alt="包含相對時間預設與絕對起訖欄位的分析時間控制項" caption="即時調查使用相對範圍；需要重現固定事件區間時使用絕對範圍。" />

### 相對範圍

相對範圍會以目前時間作為結束點。分析支援最近 15 分鐘、1 小時、6 小時、24 小時、7 天與 30 天。更新相對範圍時，結束時間會向前移到新的目前時間。

進行中的事件使用較短範圍；需要判斷變化是否超出正常基準時，使用 24 小時或更長範圍。

### 絕對範圍

絕對範圍會固定**開始**與**結束**時間。因為更新資料不會移動區間，所以適合事件回顧與共享調查。

使用圖表的縮放選取或範圍滑桿，會把全域分析區間改為所選的絕對範圍。選取**現在**則會保留目前區間長度，並把結束時間移到現在。

:::note 瀏覽器會以本地時區顯示絕對時間。不同地區的處理人員共同調查時，請將時區與共享網址一起記錄。 :::

## 更新資料

**更新**會控制分析重新載入目前專案資料的頻率：

- **關閉**會停用自動更新。
- `10s`、`30s`、`1m` 與 `5m` 會依指定間隔重複更新。
- 更新按鈕會立即重新載入，但不會改變目前設定的間隔。

每次更新都會讓相對時間向前移動；絕對時間保持固定，因此可以在不改變事件邊界的情況下重新載入。

更新頻率不要快於底層檢查排程。頁面每 10 秒更新一次，不會讓每分鐘執行一次的檢查產生額外量測。

## 閱讀圖表中繼資料

每個序列面板都會顯示資料點數量，以及資料來源或解析度。依據所選期間與保留資料，資料點可能是一筆原始量測，也可能是代表較大 Bucket 的彙總值。

- 需要精確事件時間時，使用短範圍與原始資料點。
- 觀察趨勢與比較基準時，使用彙總資料點。
- 平滑的彙總曲線不能證明每一次執行都成功。
- 資料點少於預期，可能來自檢查間隔、遺漏執行、保留政策或彙總。

將游標移到序列上，可以讀取單一時間點的數值；使用圖例則可把每條線對應到探測器、檢查、目標與位置。

## 分享可重現的檢視

分析會把探測器 ID、檢查 ID、時間模式、時間範圍、更新間隔與所選 Traceroute 執行保存在頁面網址。設定好最終範圍後再複製網址。

分享以前，請記錄：

1. 專案與預期的探測器及檢查指派。
2. 畫面顯示的時區。
3. 時間區間是相對或絕對模式。
4. 區間內的部署、維護、路由或 DNS 變更。

若共享網址引用已不存在的探測器、檢查或指派，分析會回報共享範圍無效，而不會默默替換成其他資源。

## 辨識空白與例外狀態

| 狀態               | 意義                                     | 下一步                               |
| ------------------ | ---------------------------------------- | ------------------------------------ |
| 控制項下方沒有面板 | 尚未選取探測器或檢查範圍                 | 至少選取一個探測器                   |
| 沒有有效指派       | 所選資源存在，但沒有形成有效配對         | 檢查探測器標籤、檢查選擇器與啟用狀態 |
| 範圍內沒有序列     | 指派存在，但時間區間沒有符合的保留資料點 | 擴大範圍並確認探測器正在回報         |
| 共享範圍無效       | 網址包含未知或已刪除的資源               | 重設範圍並重新建立選取項目           |
| 同步中             | 更新進行時仍顯示既有資料                 | 比較最新資料點以前先等待同步完成     |

## 調查流程

若要讓調查可以重複執行：

1. 選取足以回答問題的最小範圍。
2. 先使用涵蓋回報症狀的相對時間範圍。
3. 比較多個探測器，判斷問題是區域性或目標端全面發生。
4. 將圖表縮小到事件區間，並切換成絕對時間。
5. 判讀相關的 [Ping、TCP 與 HTTP 結果](./analyze-measurements/)或 [Traceroute 證據](./investigate-traceroute/)。
6. 分享最終網址，並與部署或網路變更交叉比對。
7. 若條件可重複出現，請建立[警示規則](/zh-TW/docs/guides/alerts-and-incidents/)，不要只依賴人工檢查圖表。

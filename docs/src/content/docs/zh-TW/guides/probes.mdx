探測器會從你想觀察的網路執行檢查。每個探測器都註冊於單一專案，並使用自己的憑證驗證身分。

## 系統需求

探測器代理程式 支援 Linux `amd64` 與 `arm64`。一般安裝需要：

- 具備 `systemd` 與 Root 權限的主機。
- 用來下載 Agent 的 `curl` 或 `wget`。
- 連到 Netstamp 控制器的對外 HTTPS 存取。
- 從主機到所有檢查目標的網路存取。

控制器不需要主動連入探測器。

## 註冊並安裝探測器

1. 選取探測器所屬的專案。
2. 開啟**探測器**並選擇**新增探測器**。
3. 輸入容易辨識的名稱與選填位置。
4. 複製產生的安裝指令。
5. 在目標 Linux 主機上以 Root 權限執行。

產生的服務安裝指令會使用控制器 URL、探測器 ID 與一次性 Secret：

```bash
sudo netstamp-agent service install \
  --url 'https://netstamp.example.com' \
  --probe-id '<probe UUID>' \
  --probe-secret '<one-time secret>'
```

請把這段指令視為憑證。不要貼到工單、聊天紀錄、多人共用的 Shell 歷史或設定管理輸出。

## 確認連線

安裝後，探測器頁面應顯示近期心跳。控制器會在可取得時記錄 Agent 版本、位址、公網 IP 資訊與支援的 IP Family。

若探測器持續離線，請在主機上確認服務與日誌：

```bash
sudo systemctl status netstamp-agent
sudo journalctl -u netstamp-agent -n 100 --no-pager
```

檔案位置、升級與復原步驟請參閱 [探測器代理程式 維運](/zh-TW/docs/operations/probe-agent/)。

## 名稱、位置與標籤

使用在結果比較中仍有意義的名稱，例如 `taipei-office` 或 `aws-tokyo-1`。位置是描述性中繼資料。

標籤會控制指派。加入 `region=tw`、`network=office` 或 `provider=aws` 等標籤，並在檢查選擇器中使用相同鍵值。變更正式環境探測器的標籤前，先閱讀[標籤與指派](/zh-TW/docs/guides/labels-and-assignments/)。

## 已啟用與上線是兩件事

- **已啟用** 控制 Netstamp 是否把檢查指派給探測器。
- **上線** 表示控制器最近是否收到心跳。

計畫性維護前請停用探測器，避免指派新的工作。已啟用但離線的探測器，在恢復或停用以前仍可能影響監控預期。

## 輪替憑證

若探測器 Secret 可能外洩，或主機擁有權移交，請輪替 Secret。用新值更新主機的服務環境後重新啟動 Agent。

確認不再需要該探測器的歷史身分與指派後才刪除。暫時故障或維護時，應改用停用。

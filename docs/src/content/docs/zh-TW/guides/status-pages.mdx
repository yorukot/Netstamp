狀態頁面可在不需要 Netstamp 帳號的情況下，公開經過挑選的監控健康資訊。每個頁面屬於一個專案，網址為 `/status/<slug>`。

## 建立狀態頁面

<ProductScreenshot src={statusPageListScreenshot} alt="包含可見性、網址代稱、狀態與操作的狀態頁面清單" caption="清單會把頁面管理功能與未登入的公開檢視分開。" />

1. 開啟專案中的**狀態頁**。
2. 選擇**新增頁面**。
3. 設定名稱與唯一的網址代稱。
4. 加入要公開的檢查。
5. 設定頁面呈現方式並儲存。

使用無痕視窗開啟公開網址，確認未登入訪客實際可看到的內容。

<ProductScreenshot src={builderScreenshot} alt="包含設定與即時服務預覽的狀態頁面建置器" caption="建置頁面時，可在旁邊的即時預覽同步檢查公開呈現。" />

## 選擇公開內容

狀態頁面應呈現對外有意義的服務，不必放入所有內部檢查。依受眾理解的服務語言整理檢查，並使用清楚的顯示名稱。

發布前，檢查名稱、探測器名稱、位置、標籤、目標與事件文字是否含有內部拓撲或客戶資料。這些欄位都不應放入密鑰。

## 解讀狀態

頁面會從所選監控資料推導健康狀態。公開頁面的代表性取決於檢查與指派的探測器，因此請確認：

- 檢查涵蓋真實使用者路徑。
- 探測器從相關網路或區域執行。
- 已停用或過期的檢查不會被當作目前證據。
- 警示與事件行為符合預期的公開訊息。

## 修改 網址代稱 或移除頁面

修改 網址代稱 會更動公開網址。完成後要更新書籤、DNS Redirect 與外部引用。

頁面不應繼續公開時，請停用或刪除。接著從未登入工作階段驗證舊網址，並移除 Reverse Proxy 或 CDN 可能保留的快取。

把狀態頁面視為公開介面：有意識地限制範圍、在監控設定變更後重新檢視，並在事件演練中測試。

分享網址前，請重新檢查底層[檢查](/zh-TW/docs/guides/checks/)與[警示行為](/zh-TW/docs/guides/alerts-and-incidents/)。

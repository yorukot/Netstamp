Ping、TCP 與 HTTP 會從不同層次回答同一條路徑的問題。調查時請依序進行：

1. **Ping：**目標是否可達？往返狀況如何？
2. **TCP：**探測器能否連上服務連接埠？
3. **HTTP：**應用程式是否回傳預期回應？請求時間花在哪個階段？

如果還不熟悉選取一或多筆指派，請先閱讀[分析範圍與時間控制項](../)。

## 選擇詳細或比較模式

需要摘要指標或最新 HTTP 結果時，選取一個探測器與一個檢查。需要判斷症狀發生在目標端或只有特定網路受到影響時，則為同一個檢查選取多個探測器。

<ProductScreenshot src={pingComparisonScreenshot} alt="比較三個探測器對同一目標 Ping 延遲的序列" caption="比較模式會為每筆有效指派保留一條線；使用圖例辨識探測器與所在位置。" />

選取多種檢查類型時，分析會分別建立 Ping、TCP 與 HTTP 面板。Traceroute 使用自己的拓樸與時間線，不會顯示成一般時間序列面板。

## 使用 Ping 調查可達性

Ping 會量測 ICMP 可達性、往返時間與封包遺失。

<ProductScreenshot src={pingSeriesScreenshot} alt="單一探測器與檢查的 Ping 摘要指標及往返時間圖表" caption="請一起判讀遺失與延遲；缺少探測器、目標與時間範圍的延遲數值並不是完整證據。" />

### 閱讀摘要

| 指標 | 告訴你的資訊               | 下一步檢查                   |
| ---- | -------------------------- | ---------------------------- |
| 平均 | 所選範圍內的典型往返時間   | 與同一探測器的基準比較       |
| 最大 | 保留資料中最差的往返量測   | 確認是單次或持續發生         |
| 遺失 | 未收到回覆的封包比例       | 比較其他探測器與下游通訊協定 |
| 成功 | 成功 Ping 結果的比例       | 確認遺失是間歇或持續發生     |
| 樣本 | 範圍內所代表的保留回覆數量 | 檢查排程、範圍與遺漏資料     |

請觀察曲線形狀，不要只看摘要數值：

- 持續性的水準位移比單一尖峰更值得處理。
- 重複尖峰可能與備份、流量突增或排程作業一致。
- 曲線缺口代表缺少證據，不表示延遲為零或該期間健康。
- 遺失與高延遲同時開始，通常指向壅塞或不穩定路徑。

### 比較探測器

| 觀察結果                       | 可能範圍                           | 驗證方式                                |
| ------------------------------ | ---------------------------------- | --------------------------------------- |
| 所有探測器同時變化             | 目標、共同上游或大範圍事件         | 比較 TCP/HTTP 與外部變更                |
| 只有一個探測器變化             | 本地接取網路、區域路徑或探測器主機 | 比較同區域的另一個探測器                |
| 鄰近探測器變化，遠端探測器沒有 | 區域電信商或 Peering 路徑          | 比較受影響與未受影響探測器的 Traceroute |
| Ping 失敗但 TCP/HTTP 成功      | ICMP 過濾或降權                    | 以服務協定作為較強的可用性證據          |

不要只用 Ping 宣告應用程式中斷。許多網路會過濾或降低 ICMP 優先級，但仍允許受監控的服務流量通過。

## 使用 TCP 調查服務存取

TCP 會量測設定的連接埠能否接受連線，以及建立連線所需時間。

<ProductScreenshot src={tcpSeriesScreenshot} alt="單一探測器與目標的 TCP 連線摘要及連線時間序列" caption="TCP 可以區分服務連接埠失敗與建立連線時間的變化。" />

摘要會顯示平均與最大連線時間、失敗比例、成功比例與連線嘗試數。請搭配 Ping 判讀：

| Ping | TCP  | 判讀                                              |
| ---- | ---- | ------------------------------------------------- |
| 成功 | 成功 | 網路路徑與服務連接埠皆可達                        |
| 成功 | 失敗 | 連接埠關閉、防火牆、Listener 故障、過載或拒絕連線 |
| 劣化 | 劣化 | 壅塞、路由不穩定或忙碌端點可能影響建立時間        |
| 失敗 | 成功 | ICMP 可能遭到封鎖，或與 TCP 受到不同處理          |
| 失敗 | 失敗 | 大範圍可達性、路由、目標或探測器網路問題          |

若只有一個探測器建立 TCP 連線較慢，請調查它的網路路徑。若所有探測器同時變化但 Ping 保持穩定，請檢查目標 Listener、Load Balancer、防火牆與連線容量。

## 使用 HTTP 調查應用程式行為

HTTP 會把傳輸層證據與回應驗證結合。依據檢查設定，結果可包含狀態驗證、Body 比對、Redirect、回應大小、最終 URL、解析位址、請求階段與 TLS 協商。

<ProductScreenshot src={httpSeriesScreenshot} alt="包含總時間、TTFB、DNS、連線與 TLS 序列的 HTTP 成功率及耗時摘要" caption="先用總時間序列找出事件，再比較請求階段，判斷時間增加在哪裡。" />

### 閱讀摘要與序列

| 指標       | 意義                                 |
| ---------- | ------------------------------------ |
| 平均總時間 | 所選範圍內的典型端到端請求時間       |
| 最大總時間 | 所選範圍內最慢的保留請求             |
| 平均 TTFB  | 收到第一個回應 Byte 前的典型等待時間 |
| 失敗       | Timeout、錯誤或未通過設定驗證的請求  |
| 成功       | 完成並符合檢查條件的請求             |
| 憑證下限   | 範圍內觀察到的最低憑證剩餘有效期     |

使用階段序列縮小可能的負責範圍：

- **DNS 增加：**Resolver 延遲、Cache miss 或名稱解析失敗。
- **Connect 增加：**路徑延遲、封包遺失、防火牆處理、Load Balancer 壓力或連線積壓。
- **TLS 增加：**握手延遲、憑證鏈處理、協定協商或攔截 Proxy。
- **TTFB 增加：**上游應用程式、相依服務、Queue 或伺服器處理時間。
- **總時間增加但 TTFB 穩定：**較可能是回應傳輸、回應大小或請求後段。

### 檢查最新保留結果

<ProductScreenshot
	src={httpTimingScreenshot}
	alt="包含憑證、請求階段、回應狀態、最終 URL 與解析位址的最新 HTTP 與 TLS 結果"
	caption="最新保留結果會詳細說明單次請求，包括實際連到哪裡，以及驗證觀察到什麼。"
/>

最新結果不受所選圖表範圍限制。即使圖表顯示較舊的絕對事件區間，它仍然代表該筆精確指派最新保留的量測。

請檢查：

1. 與圖表交叉比對以前，先確認**觀察時間**與**完成時間**。
2. **狀態**以及任何錯誤代碼或訊息。
3. **解析位址**，找出不同探測器之間的 DNS 或路由差異。
4. **最終 URL** 與 **Redirect 數量**，找出非預期的重新導向。
5. 檢查有設定回應內容驗證時的 **Body assertion**。
6. 根據保留的回應中繼資料下結論以前，確認**回應是否遭截斷**。

:::warning 除非最新結果的觀察時間位於較舊的圖表區間，否則不要把它引用為該區間的證據。 :::

## 比較 TLS 證據

為一個 HTTP/HTTPS 檢查選取多個探測器時，會開啟 TLS 憑證清單。

<ProductScreenshot src={tlsInventoryScreenshot} alt="比較三個探測器最新 HTTPS 結果的 TLS 憑證清單" caption="清單會比較每筆所選指派最新觀察到的憑證與 TLS 協商結果。" />

與最新 HTTP 結果相同，這份清單不受圖表時間範圍限制。請使用**最後觀察時間**確認資料新鮮度。

探測器之間的差異可能揭露：

- 區域 CDN Edge 提供不同憑證。
- 公司 Proxy 或 TLS Inspection 裝置。
- Split-horizon DNS 把探測器導向不同端點。
- 尚未收到憑證輪替的過期節點。
- 特定路徑上的 TLS 協定或 Cipher 支援不同。

憑證有效不代表 Hostname 驗證、狀態驗證或回應內容一定成功。請一起閱讀 HTTP 結果與憑證狀態。

## 常見錯誤

- 把不同目標或不同檢查類型當成同一個序列比較。
- 把長時間範圍的彙總結果當成精確事件時間線。
- 把缺少資料點視為成功量測。
- 把 Ping 失敗視為 TCP 或 HTTP 不可用的證明。
- 未確認時間戳記就使用最新 HTTP/TLS 面板。
- 比較探測器時忽略區域、Provider、標籤或解析位址。
- 啟用比檢查產生量測更快的頁面更新頻率。

## 將證據轉為行動

找到可重複的條件後：

1. 將圖表縮小成絕對事件區間。
2. 保存分析網址並記錄時區。
3. 比較受影響與未受影響的探測器。
4. 證據指向特定路徑問題時，使用 [Traceroute](../investigate-traceroute/)。
5. 為遺失、失敗比例或延遲等穩定門檻建立[警示規則](/zh-TW/docs/guides/alerts-and-incidents/)。

檢查定義探測器要執行的目標與量測。Netstamp 支援 Ping、TCP、HTTP 與 Traceroute。

<ProductScreenshot src={checkListScreenshot} alt="包含 Ping、HTTP、TCP 與 Traceroute 定義的檢查表格" caption="檢查清單會同時顯示四種檢查的目標、間隔與指派數量。" />

## 共通設定

每個檢查都有：

- 在結果、事件與狀態頁面中識別用途的名稱。
- 啟用狀態。
- 執行間隔與逾時。
- 控制指派的探測器選擇器。
- 類型專屬的目標與驗證設定。

請依需要的回應速度選擇間隔。較短的間隔能更快發現變化，但會增加網路流量、儲存空間與警示樣本量。逾時應小於執行間隔。

## Ping 檢查

Ping 用於量測基本 IP 可達性與往返時間。設定主機名稱或 IP 位址，以及表單提供的封包行為。

即使應用程式可用，ICMP 被過濾時 Ping 仍可能失敗。當服務可用性比 ICMP 可達性更重要時，請搭配 TCP 或 HTTP 檢查。

## TCP 檢查

TCP 用於確認主機是否接受特定連接埠的連線，適合資料庫、郵件伺服器、Proxy 與其他非 HTTP 服務。

成功連線只證明連接埠接受連線，不代表應用層協定交換正確。

<ProductScreenshot src={tcpFormScreenshot} alt="包含連接埠、逾時與 IP Family 設定的 TCP 檢查表單" caption="TCP 檢查會測試所選連接埠是否接受來自已指派探測器的連線。" />

## HTTP 檢查

HTTP 用於驗證網頁端點。依所選選項，可以設定：

- HTTP Method 與 URL。
- Request Header 與 Body。
- 接受的 Status Code。
- Response Body 必須包含的文字。
- Redirect 與 TLS 行為。
- 每次請求的逾時。

表單最多接受 50 個 Request Header、65,536 Bytes 的 Request Body、60,000 毫秒逾時，以及 1,024 字元的 Response Body 比對文字。

盡量使用穩定的健康檢查端點。避免會修改資料、觸發昂貴工作，或需要過大權限憑證的目標。

## Traceroute 檢查

Traceroute 會記錄每個被指派探測器到目標的網路路徑。比較不同探測器，或檢查事件前後路徑如何改變時最有價值。

中間路由器可能不回應，因此缺少躍點不一定代表流量在該處中斷。

## 選擇探測器

使用選擇器控制哪些探測器執行檢查。空白選擇器會指派給專案中所有已啟用的探測器。

儲存後，等待探測器更新指派並完成至少一次執行間隔，再開啟檢查或 [分析](/zh-TW/docs/guides/results-and-insight/) 確認預期探測器已送達結果。

## 編輯、停用或刪除

編輯目標、間隔、逾時、選擇器或啟用狀態會更新指派。想暫停收集但保留設定時，請停用檢查。

不再需要歷史脈絡時才刪除。移除檢查也可能影響相依的警示規則與狀態頁面，因此先檢查這些關係。

下一步，使用[結果與分析](/zh-TW/docs/guides/results-and-insight/)確認每個已指派探測器的量測資料。

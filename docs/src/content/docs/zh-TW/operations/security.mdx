Netstamp 會處理監控目標、網路位置、使用者身分、探測器憑證、通知密鑰與長期時間序列資料。請把控制器視為正式環境基礎設施。

## 強化部署邊界

- 只公開 HTTPS 反向代理。
- 將 PostgreSQL 保留在私有 Docker 或主機網路。
- 使用適當的 Firewall 與身分政策限制控制器存取。
- 設定確切的 Trusted Proxy 位址或 CIDR。
- 持續更新主機、Docker、Proxy、Database Image 與 Netstamp Image。
- 監控健康狀態、資源耗盡、憑證到期日與備份時間。

## 維護密鑰清冊

保護並備份：

- 資料庫密碼。
- Log Pseudonym Key。
- System Settings Encryption Key。
- Session 與 API Token Hash Key。
- OAuth 與 OIDC Client Secret。
- SMTP 密碼。
- 探測器 Secret。
- 個人 API 權杖。
- Webhook URL 與 Bot Token。

使用彼此獨立的隨機值。限制 `.env` 檔案權限、絕不提交到版本控制，並避免讓密鑰出現在共用 Shell History 或日誌中。

## 保護身分驗證

- 從可信任的網路建立第一位系統管理員。
- 加入第二位管理員作為復原管道。
- 不需要時停用公開註冊。
- 確認 SMTP 穩定後才強制電子郵件驗證。
- 除非供應商的使用者範圍就是預期信任邊界，否則停用 JIT Provisioning。
- 定期檢查使用中的工作階段、已連結身分、系統管理員與專案擁有者。
- 為 API 權杖設定最小權限與合理到期日。

## 將探測器視為受信任基礎設施

每個探測器都有唯一憑證，絕對不要把 `/etc/netstamp/probe.env` 複製到其他探測器。主機重建、移交、疑似外洩或意外寫入日誌後，都應輪替 Secret。暫時不應接收工作時，請停用探測器。

systemd 服務會限制權限，但仍為 ICMP 取得 Raw Network Capability。只有管理員應能修改 Agent Binary 與 Root 擁有的設定。

## 降低 HTTP 檢查密鑰權限

HTTP Header、Body、Query Value 與 Response Assertion 可能包含憑證或敏感資料。請使用專門建立且符合最小權限原則的 Token，不要使用正式使用者憑證監控端點。

能管理檢查的編輯者可以存取敏感檢查設定，因此應定期檢視成員權限。

## 檢查公開狀態資料

狀態頁面不需要登入。請檢查目標、探測器名稱、位置、標籤、事件文字、Banner URL、Footer 與其他呈現欄位。不需要精確拓撲時，請使用較粗略的位置名稱。

## 處理憑證外洩

| 外洩項目                  | 立即處理方式                           |
| ------------------------- | -------------------------------------- |
| 工作階段                  | 撤銷受影響的工作階段或全部工作階段     |
| API 權杖                  | 建立替代權杖、更新使用端，再撤銷舊權杖 |
| 探測器 Secret             | 輪替並重新安裝服務憑證                 |
| OAuth/OIDC Secret         | 在供應商端輪替，並更新控制器設定       |
| Webhook、Bot 或 SMTP 憑證 | 在目的地輪替並替換已保存數值           |
| 資料庫密碼                | 限制存取，並同步輪替資料庫與控制器數值 |
| Hash 或 Encryption Key    | 先評估失效與復原影響，再執行受控輪替   |

完成止血後，檢查日誌中是否使用過外洩數值、撤銷衍生存取權、記錄受影響時段，並測試復原後的流程。

## 私下回報安全性問題

不要在公開 Issue 發布 Exploit 細節、密鑰或個人資料。請遵循 Repository 的[安全性政策](https://github.com/yorukot/netstamp/blob/main/SECURITY.md)，並在可用時使用 GitHub Private Vulnerability Reporting。

The repository's standard Compose deployment is the recommended starting point for self-hosting. It runs three services:

| Service    | Purpose                                                                     |
| ---------- | --------------------------------------------------------------------------- |
| `postgres` | PostgreSQL 16 with TimescaleDB and a persistent named volume                |
| `migrate`  | One-shot database migration using the same Netstamp image version           |
| `netstamp` | Controller, embedded React application, API, and Linux probe install assets |

The standard stack intentionally does not include a reverse proxy or TLS automation. The `netstamp` service serves the frontend and API from one origin and publishes one host port; use your existing reverse proxy when exposing it publicly.

## Download and configure

```bash
mkdir -p /opt/netstamp
cd /opt/netstamp
curl -fsSLO https://github.com/yorukot/netstamp/releases/latest/download/compose.yaml
curl -fsSLO https://github.com/yorukot/netstamp/releases/latest/download/.env.example
cp .env.example .env
chmod 600 .env
```

Generate independent secrets:

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

Put a different value on each of these lines in `.env`:

```dotenv
DATABASE_PASSWORD=<random value>
LOG_PSEUDONYM_KEY=<random value>
SYSTEM_SETTINGS_ENCRYPTION_KEY=<random value>
AUTH_SESSION_HASH_KEY=<random value>
AUTH_API_TOKEN_HASH_KEY=<random value>
```

The required group is the only part of `.env` that must be filled for a local first start. Its values must remain stable across restarts and upgrades. Changing a hash key invalidates the associated credentials; changing the settings encryption key can make stored SMTP or external-provider credentials unreadable.

The release template is intentionally minimal. Compose supplies defaults for non-required settings; copy only the overrides you need from the [Configuration reference](/docs/reference/configuration/).

## Start the stack

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs migrate
```

The expected state is:

- `postgres` is healthy;
- `migrate` exited with status 0;
- `netstamp` is running;
- the configured port answers `/healthz` and `/api/v1/healthz`.

```bash
curl --fail http://127.0.0.1:3000/healthz
curl --fail http://127.0.0.1:3000/api/v1/healthz
```

## Image and version selection

The defaults are:

```dotenv
NETSTAMP_IMAGE=yorukot/netstamp
NETSTAMP_VERSION=latest
TIMESCALEDB_IMAGE=timescale/timescaledb:2.20.3-pg16
NETSTAMP_PORT=3000
```

The Compose file attached to a GitHub release defaults to that release's Netstamp image tag. The repository copy uses `latest` for evaluation. For a controlled installation, pin `NETSTAMP_VERSION` and `TIMESCALEDB_IMAGE` to an immutable release tag or digest that you have tested. The migration and application services always use the same Netstamp version.

## Persistent data

The database lives in the Compose volume logically named `netstamp-postgres`; Docker normally prefixes its actual name with the Compose project name. Removing containers does not remove the volume. Do not use `docker compose down -v` unless you intentionally want to destroy every project, user, probe, result, incident, and setting.

List and inspect the volume:

```bash
docker volume ls --filter name=netstamp-postgres
docker compose exec postgres psql -U netstamp -d netstamp -c 'select now();'
```

## Custom image builds

The published image includes the controller, migrations, web app, and amd64/arm64 probe binaries. To build the same image from a checkout:

```bash
docker build -f deployments/Dockerfile -t netstamp:local .
NETSTAMP_IMAGE=netstamp NETSTAMP_VERSION=local docker compose up -d
```

The published image is built with every web-tracker identifier blank, so analytics are disabled by default. Tracking is not configured in **Admin → System settings** or through the runtime configuration API.

To enable a tracker, rebuild the image and pass the corresponding web build variables as Docker build arguments:

```bash
docker build \
  -f deployments/Dockerfile \
  --build-arg VITE_NETSTAMP_POSTHOG_KEY=phc_example \
  --build-arg VITE_NETSTAMP_POSTHOG_HOST=https://us.i.posthog.com \
  --build-arg VITE_NETSTAMP_TRACKING_CONSENT_MODE=always \
  -t netstamp:tracked .
```

All supported Google Tag, Clarity, Meta Pixel, PostHog, Plausible, Umami, and consent arguments are listed in [Configuration reference](/docs/reference/configuration/). `VITE_NETSTAMP_GA_MEASUREMENT_ID` is a legacy alias for `VITE_NETSTAMP_GOOGLE_TAG_ID`, and `VITE_NETSTAMP_FACEBOOK_PIXEL_ID` is a legacy alias for `VITE_NETSTAMP_META_PIXEL_ID`; the preferred names win when both are set.

Consent mode accepts `regional`, `always`, or `immediate`. Regional mode prompts only in the configured countries, always mode prompts every visitor, and immediate mode loads configured trackers without showing the prompt.

These values are statically compiled into the web bundle. Adding `VITE_NETSTAMP_*` entries under Compose `environment:` or changing the runtime environment of an already-built container has no effect. Every `VITE_*` value is public to browsers, so never use one for a private API key, client secret, password, or other confidential value.
